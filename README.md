# LEAD-ASSISTENT

MVP-помощник для первичной обработки входящих заявок. Принимает текст заявки,
анализирует его с помощью настоящего API GigaChat и показывает карточку обращения:
компания, суть запроса, тип лида, известные и недостающие данные, уточняющие вопросы,
следующий шаг, черновик ответа и признак того, что заявку нужно передать человеку.

Веб-приложение на одной странице, на русском языке.

## 1. Что нужно установить

| Что | Зачем | Как проверить |
|-----|-------|---------------|
| Python 3.10 или новее | Язык, на котором написан сервер | Откройте PowerShell и введите `python --version` |
| Интернет | Обращения к GigaChat | - |

Больше ничего ставить не нужно: все библиотеки устанавливаются одной командой (шаг 2).

Проверить, что Python установлен:

```powershell
python --version
```

Если команда не найдена - установите Python с официального сайта python.org
(при установке отметьте галочку "Add Python to PATH").

## 2. Установка библиотек (один раз)

Откройте PowerShell в папке проекта (можно правой кнопкой по папке -> "Открыть в терминале")
и выполните по очереди:

```powershell
cd D:\LEAD-ASSISTENT
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Что здесь происходит простыми словами:

* `python -m venv .venv` - создает отдельное "окружение" (папку `.venv`), чтобы библиотеки
  проекта не смешивались с другими программами на компьютере.
* `pip install -r requirements.txt` - скачивает библиотеки из списка `requirements.txt`:
  веб-сервер (FastAPI), HTTP-клиент (requests) и модуль чтения `.env` (python-dotenv).

Активировать окружение не требуется - в командах выше Python вызывается напрямую через
`.venv\Scripts\python.exe`. Так меньше шансов столкнуться с ошибкой политики PowerShell.

## 3. Ключ GigaChat

1. Откройте личный кабинет GigaChat API (Studio): https://developers.sber.ru/gigachat
2. Создайте проект GigaChat API (если его ещё нет).
3. В проекте: "Настройки API" -> "Получить ключ".
4. Скопируйте значение поля **Authorization Key** (это готовая строка в кодировке Base64).
5. Создайте файл `.env` в папке проекта из шаблона:

```powershell
Copy-Item .env.example .env
notepad .env
```

6. Впишите ключ в `.env` в строку `GIGACHAT_API_KEY=`:

```
GIGACHAT_API_KEY=ваш_ключ_сюда
```

Правильно:

```
GIGACHAT_API_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

Неправильно (кавычки, пробелы, перенос строки внутри ключа - так ключ не сработает):

```
GIGACHAT_API_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

### Про тариф (scope)

В `.env` есть параметр `GIGACHAT_SCOPE`:

| Значение | Кому подходит |
|----------|---------------|
| `GIGACHAT_API_PERS` | физическим лицам, бесплатный режим (по умолчанию) |
| `GIGACHAT_API_CORP` | ИП и юрлицам с оплатой по факту (pay-as-you-go) |
| `GIGACHAT_API_B2B` | ИП и юрлицам с предоплаченными пакетами токенов |

### Про модель

В `.env` есть параметр `GIGACHAT_MODEL`. По умолчанию `GigaChat-2-Max` - она лучше всего
следует сложным инструкциям. Если нужна скорость или экономия - поменяйте на
`GigaChat-2-Pro` или `GigaChat-2`.

### Сертификаты (certs/)

GigaChat работает на сертификатах российского УЦ Минцифры, а их корневого сертификата
нет в стандартном наборе, которым пользуется библиотека `requests` - без него проверка
защищённого соединения не проходит и приложение отвечает «Не удалось проверить
сертификат сервиса GigaChat».

Поэтому в проекте лежит файл `certs/russian_trusted_root_ca.pem` - корневой сертификат
УЦ Минцифры, скачанный с официального адреса и сверенный по отпечатку SHA-256
(`D26D2D0231B7C39F92CC738512BA54103519E4405D68B5BD703E9788CA8ECF31`). Проверка
сертификатов при этом остаётся включённой - безопасность не снижается.

Если этот файл случайно удалён, приложение вернёт понятную ошибку. Скачать заново можно
отсюда: https://gu-st.ru/content/Other/doc/russian_trusted_root_ca.cer (файл нужно
переименовать в `certs/russian_trusted_root_ca.pem` и привести к текстовому формату PEM).

Если по какой-то причине сертификаты установить не получается, в `.env` можно добавить
`GIGACHAT_VERIFY_SSL=false` - тогда проверка будет отключена (так же работает
официальный SDK GigaChat). Это менее безопасно, поэтому включайте только если по-другому
не получается.

### Безопасность

* Файл `.env` содержит секрет и добавлен в `.gitignore` - в git он не попадёт.
* Ключ не отправляется в браузер и не пишется в журналы работы приложения.
* Никогда не присылайте ключ в чат и не вставляйте его в код.

## 4. Запуск

### Самый простой способ - двойной клик

В папке проекта есть два файла:

* **setup.bat** - установка (создаёт окружение, ставит библиотеки, создаёт `.env`).
  Запустите его один раз двойным кликом.
* **start.bat** - запуск приложения. Двойной клик - и через пару секунд откроется
  браузер со страницей приложения. Чтобы остановить, закройте это окно.

### Через PowerShell (то же самое)

```powershell
cd D:\LEAD-ASSISTENT
.\.venv\Scripts\python.exe app.py
```

В консоли появится:

```
============================================================
 LEAD-ASSISTENT - обработка входящих заявок
 Откройте в браузере: http://localhost:8000
 Остановка: Ctrl+C
============================================================
```

Откройте в браузере **http://localhost:8000** - приложение работает на вашем компьютере,
данные никуда не уходят, кроме запросов к GigaChat.

Чтобы остановить приложение, в консоли нажмите **Ctrl+C**.

## 5. Как пользоваться

На странице форма обращения: **Имя**, **Телефон**, **E-mail** и **Текст заявки**.

Обязательны текст заявки и хотя бы одно поле контакта (имя, телефон или e-mail).
Если чего-то не хватает, поля подсвечиваются красным, а подсказка объясняет, что
именно заполнить. Формат телефона и e-mail тоже проверяется: «не-почта» или номер
из двух цифр не пройдут.

| Шаг | Действие | Что произойдёт |
|-----|----------|----------------|
| 1 | Откройте **http://localhost:8000** | Сверху плашка про состояние ключа GigaChat, ниже форма обращения и 3 кнопки-примера |
| 2 | Нажмите кнопку с тестовой заявкой | Заполнятся все поля: имя, телефон, e-mail и текст |
| 3 | Нажмите **«Обработать»** | Появится счётчик секунд, обычно ждать 4-11 секунд |
| 4 | Дождитесь зелёной строки **«Обработка завершена за N с»** | Ниже появится карточка «Результат обработки» с 10 блоками |

Пока идёт обработка, кнопка «Обработать» неактивна, чтобы не отправить заявку дважды.
Если что-то пошло не так, внизу появится блок с понятным текстом ошибки (технические
детали - в раскрывающемся блоке «Подробнее» - их можно скопировать и прислать).

### Кнопки

| Кнопка | Что делает |
|--------|-----------|
| **Обработать** (или Ctrl+Enter прямо в поле) | Отправляет форму на разбор в GigaChat |
| **Скачать результат** | Сохраняет готовый разбор в текстовый файл `.txt` - с контактами, всеми полями и черновиком ответа |
| **Очистить** | Стирает все поля формы, карточку результата и сохранённую копию (нужно, чтобы начать с нуля) |

### Результат не пропадает после перезагрузки

Заполненная форма и последний разбор хранятся в браузере (localStorage), поэтому можно
спокойно нажать F5 или открыть вкладку заново - поля и карточка вернутся на место. В шапке
восстановленной карточки появляется пометка **«восстановлено из сохранения»**: это значит,
что новый запрос к GigaChat не выполнялся, показан прежний результат.

Сохранение работает в браузере, в котором открыта страница. Скачанный файл `.txt` ни от чего
не зависит - он останется на вашем компьютере. Для реальных заявок с персональными данными
хранение лучше перенести на сервер: в MVP этого нет. Если браузер работает в приватном
режиме, сохранение просто отключится - приложение продолжит работать, результат будет
храниться только до перезагрузки.

### Что показывает карточка

| Поле | Что это |
|------|---------|
| Компания | Название компании из заявки или «не указано» |
| Суть запроса | 1-2 предложения о том, чего хочет клиент |
| Тип лида | Целевой / нецелевой / неясно |
| Известные данные | Только то, что реально есть в заявке |
| Чего не хватает | Важные данные, которых нет в заявке. Если заявка ушла человеку - что нужно менеджеру для разбора |
| Уточняющие вопросы | 1-2 вопроса клиенту, если данных мало. Для заявок, переданных человеку, вопросы не задаются |
| Следующий шаг | Что делать менеджеру |
| Черновик ответа | Текст ответа клиенту без неподтверждённых обещаний |
| Нужен человек | Да / Нет |
| Причина передачи человеку | Почему заявку надо обработать вручную |

### Правила, которые соблюдает AI

* Не выдумывает данные: нет данных - «не указано».
* Не обещает цены, сроки, скидки и другие условия, которых нет в заявке.
* Задаёт 1-2 уточняющих вопроса, если данных недостаточно.
* Передаёт человеку жалобы, конфликты, угрозы отказа, требования возврата
  и нестандартные запросы; черновик ответа в таких случаях нейтральный,
  без неподтверждённых обещаний.
* Если заявка передана человеку, уточняющие вопросы клиенту не задаются, а в списке
  «Чего не хватает» указывается, что нужно менеджеру для разбора. Пустые списки
  в карточке подписаны понятно: «все ключевые данные есть» или
  «не задаются: заявка передана человеку» - вместо «ничего не выявлено».

## 6. Проверка готовности

Прогоните три тестовые заявки кнопками на странице:

| Тест | Ожидаемый результат |
|------|---------------------|
| Тест 1: полная заявка | Тип лида «целевой», нужный человек - «Нет», данные заполнены, цена и сроки не выдуманы |
| Тест 2: неполная заявка | Тип лида «целевой» (намерение купить ясно), но данных мало: есть список «Чего не хватает» и 1-2 уточняющих вопроса |
| Тест 3: конфликтная заявка | Нужен человек - «Да», указана причина, черновик ответа нейтральный без обещаний и компенсаций |

Тип лида «неясно» появляется, когда непонятно, о чём вообще запрос: например, если
вставить в поле текст «Добрый день» без указания предмета запроса. В тестовых
заявках такой случай не встречается - намерение во всех трёх читается однозначно,
поэтому тип «целевой», а нехватка данных показывается отдельно (списком
«Чего не хватает» и вопросами).

## 7. Устройство проекта

```
setup.bat         установка библиотек и создание .env (двойной клик)
start.bat         запуск приложения и открытие браузера (двойной клик)
certs/            корневой сертификат УЦ Минцифры (нужен для защищённого соединения)
app.py            веб-сервер: страница, приём заявки, выдача тестовых примеров
gigachat_api.py   обмен с GigaChat: токен, запрос к модели, разбор ответа
privacy.py        обезличивание персональных данных перед отправкой в GigaChat
anonym_log.py     журнал обезличивания: статистика в CSV, без самих данных
bitrix24_client.py отправка разобранной заявки в Битрикс24 (входящий вебхук)
env_config.py     чтение файла .env с учётом разных кодировок
prompts.py        правила работы AI, схема ответа, тестовые заявки
static/index.html страница приложения
static/favicon.svg  значок сайта (иконка во вкладке браузера)
tools/test_privacy.py  проверка слоя обезличивания (59 проверок, без интернета)
tools/test_bitrix24.py проверка отправки в Битрикс24 (24 проверки, без интернета)
requirements.txt  список библиотек
.env.example      шаблон файла с ключом (значения пустые)
.gitignore        список файлов, которые не попадают в git
README.md         эта инструкция
ИЗМЕНЕНИЯ_ПО_ЗАМЕЧАНИЯМ.md  что доработали 21.10.2026 по замечаниям и как это повлияло на результат
ИЗМЕНЕНИЯ_ПО_ЗАМЕЧАНИЯМ.docx  то же самое в формате Word (для открытия и печати)
```

Приложение состоит из двух частей:

* **Сервер (Python)** - принимает заявку, сам ходит в GigaChat и возвращает готовый JSON.
  Ключ живёт только здесь, в браузер он не попадает.
* **Страница (HTML)** - то, что вы видите в браузере. Она лишь отправляет текст на сервер
  и показывает готовую карточку с русскими названиями полей.

Как устроен разбор заявки:

1. Приложение получает токен доступа GigaChat (токен живёт 30 минут и кэшируется).
2. Текст заявки проходит через слой обезличивания: имена, телефоны, e-mail, адреса
   и другие персональные данные заменяются метками вида `[ТЕЛЕФОН_1]`.
3. В модель уходит только обезличенный текст вместе с правилами и схемой ответа
   (режим `response_format: json_schema`), поэтому модель возвращает готовый JSON
   и не видит реальных персональных данных.
4. Когда ответ получен, метки заменяются обратно реальными значениями - в карточке
   вы видите настоящие имя, телефон и адрес.
5. Если модель вдруг ответит не-JSON, приложение повторяет запрос обычным текстом
   с требованием JSON и разбирает ответ самостоятельно.
6. Ответ приводится к единому виду: пустые поля заменяются на «не указано»,
   тип лида проверяется по списку допустимых значений.

## 8. Что не входит в MVP

CRM, база данных, авторизация пользователей, интеграция с мессенджерами,
автоматическая загрузка заявок из почты или CRM. Приложение - одностраничный
инструмент, который работает на вашем компьютере.

## 9. Если что-то не работает

| Сообщение | Что делать |
|-----------|-----------|
| «Не задан ключ авторизации GigaChat» | Не создан `.env` или в нём пустое `GIGACHAT_API_KEY`. Проверьте шаг 3 |
| «Ключ авторизации отклонён» | Ключ введён с ошибкой (лишние кавычки, пробелы, перенос строки) или истёк. Сгенерируйте новый в личном кабинете |
| «Нет связи с сервисом GigaChat» | Проверьте интернет. Для доступа к Sber API нужен VPN-сервис из белого списка |
| «Сервис GigaChat временно недоступен» | Сервис перегружен или ведёт технические работы, попробуйте позже |
| «Слишком много запросов к GigaChat» | Подождите минуту и повторите |
| «AI вернул ответ в неожиданном формате» | Повторите обработку, при устойчивых сбоях попробуйте модель `GigaChat-2-Pro` |
| В консоли ошибка про порт 8000 | Порт занят другой программой. Остановите её или поменяйте порт в последней строке `app.py` (`port=8000`) |
| Заявка не появилась в Битрикс24 | Проверьте, что в `.env` есть `B24_WEBHOOK_URL`, и что программа перезапущена после правки. В консоли должно быть «Битрикс24: входящий вебхук найден». Ошибка создания лида видна в журнале: `b24.lead.failed` — вебхук неверный или не хватает прав, `b24.lead.network_error` — нет связи с Битрикс24 |
| PowerShell ругается на `python` | Python не добавлен в PATH. Переустановите Python с галочкой "Add Python to PATH" |

Журнал работы приложения виден в консоли, где вы запустили `python app.py`.

### Что видно в окне консоли

Окно консоли должно оставаться открытым, пока работает программа. В нём
видны запросы браузера к серверу - это нормально, а не ошибки:

```
INFO:     127.0.0.1 - "GET / HTTP/1.1" 200 OK
INFO:     127.0.0.1 - "GET /api/samples HTTP/1.1" 200 OK
INFO:     127.0.0.1 - "GET /api/health HTTP/1.1" 200 OK
INFO:     127.0.0.1 - "POST /api/analyze HTTP/1.1" 200 OK
```

* `200 OK` - запрос выполнен успешно.
* `POST /api/analyze` - идёт разбор заявки (занимает несколько секунд).
  Строка появляется сразу, а результат приходит через несколько секунд.
* Строки вида `GET /health 404 Not Found` в журнале **не появляются** - они
  специально скрыты. Их присылает OpenCode (настольное приложение перебирает
  локальные порты в поисках своего сервера) - к нашей программе это отношения
  не имеет. Строка `GET /favicon.ico` тоже не появляется: у страницы есть
  свой значок `static/favicon.svg`.
* Если такая строка всё же видна - значит, запущена старая версия программы.
  Перезапустите сервер (`Ctrl+C`, затем `python app.py`).
* Красных трассировок (`Traceback`) в консоли тоже быть не должно. Раньше они
  появлялись, если браузер закрывал соединение на середине запроса (например,
  страницу обновили в момент обработки заявки). Теперь такие случаи тихо
  игнорируются - на работу программы они и раньше не влияли.

## 10. Защита персональных данных

Перед отправкой в GigaChat текст заявки проходит через слой обезличивания
(`privacy.py`). Модель не видит реальных персональных данных - вместо них
в тексте стоят метки:

| Что найдено в заявке | Как это выглядит в запросе к модели |
|----------------------|-------------------------------------|
| Имя и фамилия | `[ИМЯ_1]` |
| Телефон | `[ТЕЛЕФОН_1]` |
| Адрес электронной почты | `[EMAIL_1]` |
| Почтовый адрес | `[АДРЕС_1]` |
| Паспортные данные | `[ПАСПОРТ_1]` |
| СНИЛС | `[СНИЛС_1]` |
| ИНН или ОГРН | `[ИНН_1]` |
| Номер банковской карты | `[КАРТА_1]` |
| Дата рождения | `[ДАТА_РОЖДЕНИЯ_1]` |
| Ник или ссылка на мессенджер | `[МЕССЕНДЖЕР_1]` |

Как это устроено:

* Соответствие «метка - реальное значение» хранится только в памяти текущего
  запроса. Оно не записывается в файлы и в журнал и исчезает сразу после ответа.
  Если два человека одновременно отправят заявки, их данные не перепутаются.
* Одинаковые значения получают одну и ту же метку: два упоминания одного
  телефона превращаются в `[ТЕЛЕФОН_1]`, а не в две разные метки.
* После ответа модели метки заменяются обратно реальными значениями, поэтому
  в карточке и в черновике ответа вы видите настоящие данные.
* Названия компаний не маскируются: «Альфа-Логистик» и «ООО Ромашка» остаются
  в тексте, иначе модель не сможет заполнить поле «Компания».
* Слой работает молча: на странице ничего не появляется и не меняется.

Что важно знать:

* Имена распознаются по словарю русских имён и по типичным фамильным окончаниям.
  Редкое имя без фамилии может не распознаться, а слово с заглавной буквы,
  похожее на фамилию, может быть замаскировано зря. Если имя введено в поле
  «Имя» формы, оно маскируется всегда - независимо от словаря.
* Адрес распознаётся по словам-подсказкам: «г.», «ул.», «д.», «кв.», «обл.»,
  «пр-т», «шоссе» и подобным. Адрес, записанный без таких подсказок, может
  остаться незамеченным.
* Суммы («1,5 млн рублей»), количество рабочих мест, номера заказов, названия
  компаний и моделей не маскируются.

Проверить слой можно без интернета и без запуска сервера:

```
.venv\Scripts\python.exe tools\test_privacy.py
```

Скрипт прогоняет 59 проверок: что обязано маскироваться, что маскировать нельзя,
точность обратной подстановки и независимость одновременных запросов.

### Журнал обезличивания

Каждая обработанная заявка оставляет строку в файле
`Журнал_анонимизации.csv` в папке программы. Файл открывается в Excel
двойным кликом (разделитель - точка с запятой, кодировка подобрана так,
чтобы русский текст не превращался в «кракозябры»).

| Колонка | Что внутри | Пример |
|---------|------------|--------|
| дата_время | Когда обработана заявка | 2026-10-22T23:50:12+03:00 |
| всего_меток | Сколько всего заменено | 3 |
| по_типам | Какие данные и сколько раз | EMAIL:1, ИМЯ:1, ТЕЛЕФОН:1 |
| символов_в_заявке | Длина текста | 298 |
| статус | Чем закончилось | готово / ошибка модели |

Что важно: **самих персональных данных в журнале нет** - только количество
и типы найденного. По журналу нельзя прочитать ни имя, ни телефон, ни почту:
он нужен, чтобы видеть, что слой работает, и замечать всплески.

* Если журнал не нужен, его можно удалить - он создастся заново при следующей
  заявке.
* Другой путь к файлу задаётся переменной `ANON_LOG_PATH` (например, на сетевой
  диск). Если файл не удаётся записать, заявка всё равно обрабатывается -
  в консоли появится предупреждение.
* Проверка журнала без интернета:

  ```
  .venv\Scripts\python.exe tools\test_anonym_log.py
  ```

## 11. Отправка заявок в Битрикс24

После разбора заявки программа создаёт в Битрикс24 **лид** через входящий вебхук.

### Что настроить

1. В Битрикс24: **Разработчикам → Другое → Входящий вебхук**. Выберите
   пользователя, от чьего имени будут создаваться лиды, и выдайте права:
   CRM, Задачи, Уведомления (im). Скопируйте адрес вебхука — он выглядит так:

   ```
   https://ваш-портал.bitrix24.ru/rest/1234567/abcdef1234567890/
   ```

2. Впишите этот адрес в файл `.env`:

   ```
   B24_WEBHOOK_URL=https://ваш-портал.bitrix24.ru/rest/1234567/abcdef1234567890/
   ```

   и перезапустите программу. При старте в окне консоли появится строка
   «Битрикс24: входящий вебхук найден…». Если вебхука нет, будет написано,
   что заявки в CRM не попадут — на остальную работу это не влияет.

3. Если заявки должны сразу закрепляться за конкретным менеджером, добавьте
   его ID:

   ```
   B24_ASSIGNED_BY_ID=5
   ```

   ID сотрудника виден в адресной строке Битрикс24 (`…/company/5/`) или в
   профиле сотрудника. Если строку не задавать, лиды распределятся по правилам
   вашего портала.

### Что попадает в лид

| Поле лида | Откуда берётся |
|-----------|----------------|
| Название (TITLE) | Краткая суть заявки из карточки разбора |
| Имя, фамилия, отчество | Поле «Имя» формы |
| Телефон | Поле «Телефон» формы |
| E-mail | Поле «E-mail» формы |
| Комментарий (COMMENTS) | Исходный текст заявки и вся карточка разбора: известные данные, чего не хватает, уточняющие вопросы, следующий шаг, черновик ответа, нужен ли человек |
| Источник | `WEBFORM` (заявка с сайта) |
| Ответственный | `B24_ASSIGNED_BY_ID`, иначе — по правилам Битрикс24 |

### Важные детали

* Отправка идёт **в фоне**: карточка на экране появляется сразу, лид создаётся
  параллельно. Если Битрикс24 недоступен или адрес вебхука неверный, разбор
  заявки всё равно работает — в консоли появится строка
  «Битрикс24: лид не создан…» или «Битрикс24: нет связи с порталом…».
* При успехе в консоли пишется «Битрикс24: лид создан, номер N» — по этому
  номеру лид можно найти в CRM.
* Ответственному менеджеру приходит уведомление в Битрикс24: «Новая заявка
  LEAD-ASSISTENT: … Лид №N». Если заявка требует человека (жалоба, конфликт),
  уведомление приходит с пометкой «[Требуется человек]» и причиной.
  Получатель — `B24_ASSIGNED_BY_ID`, иначе владелец вебхука.
* Имя из формы разбирается на части так: одно слово — Имя; два слова — Имя и
  Фамилия; три слова — Фамилия, Имя и Отчество (как в паспорте).
* После создания лида ответственному менеджеру приходит уведомление в Битрикс24:
  «Новая заявка LEAD-ASSISTENT: <суть>. Лид №N»; для жалоб — с пометкой
  «[Требуется человек]» и причиной. Получатель — `B24_ASSIGNED_BY_ID`, иначе
  владелец вебхука.
* В журнал не пишутся персональные данные: только код ответа и номер
  созданного лида.
* Повторное нажатие «Обработать» создаст ещё один лид — для другой заявки
  это правильное поведение.
* Проверка без интернета и без создания реальных лидов:

  ```
  .venv\Scripts\python.exe tools\test_bitrix24.py
  ```
